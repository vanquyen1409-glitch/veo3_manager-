# VEO3 Manager — Packaging & Release Guide

## TL;DR

| Target              | Command (host OS)                | Output                                  |
| ------------------- | -------------------------------- | --------------------------------------- |
| Windows amd64       | `make windows` (Windows host)    | `build/bin/veo3-manager.exe` + `*-installer.exe` |
| Windows amd64+arm64 | `make windows-arm64`             | universal NSIS installer                |
| macOS universal     | `make macos` (macOS host)        | `build/bin/veo3-manager.app` + `*.dmg`  |
| macOS Intel only    | `make macos-intel`               | `*.app` + `*.dmg` (amd64)               |
| macOS Apple Silicon | `make macos-arm64`               | `*.app` + `*.dmg` (arm64)               |
| Linux amd64         | `make linux` (Linux/WSL2 host)   | `veo3-manager` + `*.AppImage`           |
| All platforms (CI)  | `git push origin v0.1.0`         | GitHub Actions builds + releases all 3  |

## Hard truth about cross-compiling

Wails v2 uses CGO + the **native** webview for each OS:

| OS      | Webview     | Toolchain needed                          |
| ------- | ----------- | ----------------------------------------- |
| Windows | WebView2    | MSVC / MinGW + Edge WebView2 runtime      |
| macOS   | WKWebView   | Xcode + macOS SDK (Apple-only)            |
| Linux   | WebKitGTK   | gcc + libgtk-3-dev + libwebkit2gtk-4.0-dev |

**You cannot cross-compile between these from a single host.** That's a Wails architectural limit, not a config issue. The realistic options:

1. **Build natively on each OS** (your laptop / a VM / a friend's machine).
2. **Use the GitHub Actions workflow** at `.github/workflows/build.yml` — it spawns one runner per OS and produces all three artifacts on `git push origin v<version>`.
3. **Linux only**: WSL2 on Windows works perfectly (`wsl --install`, then run `make linux` inside Ubuntu).

## Step 1 — Icon & metadata

The app icon lives at `build/appicon.png` (1024×1024). Wails auto-derives:

- `build/windows/icon.ico` — multi-size (256/128/64/48/32/16) — regenerated if absent.
- macOS `.icns` — generated at build time from `appicon.png` and embedded in the `.app` via `Info.plist`'s `CFBundleIconFile`.
- Linux uses `appicon.png` directly via the `.desktop` file.

### Regenerating the included icon

A clean, programmatic icon is generated by:

```powershell
powershell -ExecutionPolicy Bypass -File build/scripts/generate-icon.ps1
```

This produces a flat-modern indigo→violet play-button icon. Re-run anytime you tweak the script.

### Replacing with an AI-generated icon

If you'd rather use an AI-generated icon, drop a 1024×1024 PNG at `build/appicon.png` and **delete `build/windows/icon.ico`** so Wails regenerates the multi-size version.

Suggested prompt (Imagen 4 / Midjourney / DALL·E):

> Flat modern app icon, 1024x1024, rounded square, deep indigo to violet diagonal gradient (#4F46E5 → #7C3AED), centered solid white play triangle, two small subtle film-strip notches on left & right edges, soft inner highlight on top, no text, no border, transparent background outside the rounded square, sharp geometry, vector-style, premium SaaS app aesthetic.

After dropping the new file in:

```bash
# Windows: also regenerate the .ico (Wails will do this on next build if missing)
rm build/windows/icon.ico
```

Templates that consume these fields:

- `build/windows/info.json` — Windows VS_VERSIONINFO (uses LCID `0409` = en-US).

- `build/darwin/Info.plist` — macOS bundle (identifier `com.vanquyen.veo3manager`).

## Step 2 — Windows build details

`build/scripts/build.ps1` runs:

```powershell
wails build `
  -platform windows/amd64 `
  -ldflags "-s -w -X main.version=$Version -X main.buildDate=$BuildDate" `
  -trimpath `
  -clean `
  -webview2 embed `
  -nsis
```

Each flag:

| Flag | Effect |
| --- | --- |
| `-platform windows/amd64` | Target OS/arch. Use `windows/arm64` for ARM Windows (Surface Pro X etc). |
| `-ldflags "-s -w -X ..."` | `-s` strips symbol table, `-w` strips DWARF debug info (smaller binary, no `panic` source-line info). `-X` injects `main.version` & `main.buildDate` at link time. |
| `-trimpath` | Removes absolute filesystem paths from the binary — smaller and reproducible. |
| `-clean` | Wipes `build/bin/` first to avoid stale artifacts. |
| `-webview2 embed` | Bundles the Edge WebView2 bootstrap installer inside the .exe. Adds ~2 MB but the app installs WebView2 itself on first launch on a clean Windows. Other modes: `download` (fetches at runtime), `browser` (opens the user's browser to download), `error` (errors out). `embed` is the friendliest for end users. |
| `-nsis` | Also produces a Setup-style installer at `build/bin/veo3-manager-amd64-installer.exe`. Requires `makensis` on PATH. |

Then UPX is applied:

```powershell
upx --best --lzma --compress-resources=0 --no-progress veo3-manager.exe
```

- `--best` + `--lzma` = maximum compression (~63% saved).
- `--compress-resources=0` = **critical**: keeps PE resource directory uncompressed so Windows still reads VERSIONINFO (Properties → Details) and the embedded icon. Without this, the exe shows up with a blank icon and empty Properties.

### Result on this build

- `veo3-manager.exe`: **8.13 MB** (down from 21.86 MB raw)
- `veo3-manager-amd64-installer.exe`: **11.47 MB**

## Step 3 — macOS build details

```bash
bash build/scripts/build-macos.sh 0.1.0 universal
```

`-platform darwin/universal` tells Wails to build amd64 + arm64 in parallel and `lipo` them into one fat binary. Choose `amd64` for Intel-only or `arm64` for Apple Silicon-only if size matters (each arch alone is roughly half the universal size).

DMG creation: prefers `create-dmg` (`brew install create-dmg`) for a polished install window with the drag-to-Applications layout; falls back to built-in `hdiutil`.

### Code signing & notarization

Without an Apple Developer ID ($99/yr), users see "VEO3 Manager.app cannot be opened because the developer cannot be verified". They can right-click → Open the first time, but for a real product you want to sign + notarize.

Stub commands are commented in `build/scripts/build-macos.sh`. The required secrets for CI: `APPLE_ID`, `APPLE_APP_PASSWORD`, `APPLE_TEAM_ID`, `IDENTITY` (the cert subject CN), and the `.p12` cert imported into the runner keychain. Add them as GitHub Actions repository secrets and uncomment the `codesign` / `notarytool` blocks.

## Step 4 — Linux build details

```bash
bash build/scripts/build-linux.sh 0.1.0 amd64
```

### Distribution

Two simple options for end users:

1. **Plain binary** — ship `build/bin/veo3-manager` directly. Users `chmod +x` and run. They need WebKitGTK installed (`apt install libwebkit2gtk-4.0-37` on Debian/Ubuntu). Smallest, but distro-dependent.
2. **AppImage** — ship `VEO3-Manager-0.1.0-amd64.AppImage`. Single file, runs on most distros (glibc 2.28+), no install needed. The script auto-downloads `linuxdeploy` on first run.

For wider distribution: `.deb` (via `nfpm` or `dpkg-deb`), `.rpm` (rpmbuild), Flatpak, Snap. Ask if you need any of these set up.

## Step 5 — Single-command multi-platform build

### Local: `make`

```bash
make windows    # on Windows
make macos      # on macOS
make linux      # on Linux / WSL2
```

`make all` picks the right target for the current host.

### CI: GitHub Actions (the *only* true single-command path)

```bash
git tag v0.1.0
git push origin v0.1.0
```

`.github/workflows/build.yml` does the rest:

- Spawns one runner per OS (`windows-latest`, `macos-14` for arm64, `ubuntu-22.04`).
- Each installs its toolchain (NSIS+UPX on Windows, create-dmg on macOS, gtk/webkit deps on Linux), runs the matching script, uploads artifacts.
- On a `v*` tag, a final job downloads all artifacts and creates a GitHub Release.

`workflow_dispatch` (manual run) is also supported with a `version` input.

## Tools used

| Tool | Why | Install |
| --- | --- | --- |
| `wails` | Build orchestrator | `go install github.com/wailsapp/wails/v2/cmd/wails@v2.12.0` |
| `upx` | Binary compression | Win: `winget install upx`; Linux: `apt install upx`; mac: `brew install upx` |
| `makensis` | Windows installer | `choco install nsis` or download from nsis.sourceforge.io |
| `create-dmg` | macOS installer | `brew install create-dmg` |
| `linuxdeploy` | Linux AppImage | auto-downloaded by `build-linux.sh` |

All of these are pre-installed by the GitHub Actions workflow.
